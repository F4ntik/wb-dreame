# Проверка уборки у входной двери

Пример `wb-rules` считает открытия одного контакта за весь день по местному времени контроллера. В вечернем окне он отправляет одну проверку на локальный `/dreame/api/preview`, если накопился заданный порог. Таймер проверяет порог даже без новых открытий. Проверка доступна при выключенном управлении и не запускает уборку. Правило не входит в пакет и устанавливается вручную.

1. Сохраните копию `entrance-preview.json.example` на контроллере как `/etc/wb-rules/dreame-entrance-preview.json`. Храните её локально и ограничьте доступ к файлу. В `contact` укажите `устройство/канал` проверенного контакта. В `openValue` запишите фактическое значение открытой двери, строку `"0"` или `"1"`.
2. Возьмите `map.id` и `map.revision` из ответа `./api/state` открытой панели. В `target` укажите `{"kind":"rooms","rooms":[...]}` с числовыми ID комнат либо `{"kind":"zone","zone":[...]}` с четырьмя целыми координатами Dreame `[x1,y1,x2,y2]`. Углы должны идти в порядке возрастания по обеим осям. Выбранную цель сверьте на карте. При смене карты проверьте цель заново и вручную обновите привязку.
3. Настройте порог и окно в пределах одних суток. Включите `enabled`, затем положите одну копию `entrance-preview.js` в `/etc/wb-rules/`. Если правило уже установлено, замените старый JS-файл при обновлении драйвера. Пример использует `/usr/bin/curl` с поддержкой Unix-сокетов и рассчитан на штатный `wb-rules`, работающий от `root`. После правки JSON обновите время изменения файла правила, чтобы `wb-rules` перечитал привязку. Результат смотрите в журнале `wb-rules`.

Начальное и повторно полученное сохранённое MQTT-значение задаёт исходное положение двери. В счёт идут только переходы из закрытого состояния в открытое с выдержкой 500 мс и при исправном контакте. Счётчик переживает перезапуск и относится только к текущей дате, выбранному контакту и его полярности. Отметка уже сделанной попытки сохраняется отдельно, поэтому ошибки связи, перезапуск и изменение привязки в тот же день не вызывают второй запрос.

Стендовая проверка запускается из корня репозитория командой `node --test examples/entrance-preview.test.cjs`. Пример использует `readConfig`, `trackMqtt`, `PersistentStorage` и `spawn` из [документации wb-rules 2.46.5](https://github.com/wirenboard/wb-rules/blob/v2.46.5/README.md).
