# Пылесосы Dreame в Wiren Board

Панель для Dreame L40 Ultra и L40s Pro Ultra в штатном веб-интерфейсе Wiren Board. На карте видно, где пылесос сейчас и где уже помыл пол. Здесь же можно выбрать комнаты в нужном порядке, задать прямоугольную зону, включить CleanGenius или открыть карту прошлой уборки. Home Assistant для работы не нужен. Связь с роботом идёт через облако Dreamehome.

**[Скачать пакет для Wiren Board](https://github.com/F4ntik/wb-dreame/releases/download/v0.1.0/wb-mqtt-dreame_0.1.0_all.deb)** · [Что изменилось](CHANGELOG.md) · [Результаты проверок](docs/COMMISSIONING.md)

| Совместимость | Что известно |
|---|---|
| Контроллер | Проверено на WB 8.5 с WB-2609, Debian 13 (Trixie), arm64 и Python 3.13. Для Debian 11 этот пакет не подходит. |
| L40s Pro Ultra | Проверен на реальном роботе с кодом модели `dreame.vacuum.r9419a`. |
| L40 Ultra | В драйвере предусмотрены `dreame.vacuum.r2492a`, `dreame.vacuum.r2492b` и `dreame.vacuum.r2492j`. Для этих вариантов пока нет проверки на оборудовании. |
| Учётная запись | Нужен аккаунт Dreamehome с привязанным роботом и доступом к интернету. В первый раз укажи тот же регион, что в приложении. |

## Установка

Подставь адрес своего контроллера вместо `WB_ADDRESS`. Команды предполагают SSH-доступ root; при другой учётной записи используй обычный для неё способ повышения прав.

Открой PowerShell в папке, куда скачал пакет, и проверь систему контроллера.

```powershell
ssh root@WB_ADDRESS "cat /etc/wb-release /etc/os-release; dpkg --print-architecture; python3 --version; findmnt -T /mnt/data/etc"
```

Пакет использует системные зависимости из APT. Скопируй его на контроллер и посмотри, какие изменения предложит APT. Если для установки требуется сменить релиз WB или удалить компоненты домашней автоматики, прерви установку.

```powershell
scp ".\wb-mqtt-dreame_0.1.0_all.deb" root@WB_ADDRESS:/root/wb-mqtt-dreame_0.1.0_all.deb
ssh root@WB_ADDRESS "apt-get -s install /root/wb-mqtt-dreame_0.1.0_all.deb"
```

После симуляции открой `ssh root@WB_ADDRESS`. Перед **первой** установкой проверь в разделе «Устройства», свободно ли имя `dreame_l40_1`. Если установлена утилита `mosquitto_sub`, сохранённые сообщения для этого имени можно посмотреть на самом контроллере:

```sh
mosquitto_sub -h 127.0.0.1 -t '/devices/dreame_l40_1/#' -W 3 -F '%t'
```

При свободном имени команда завершится по тайм-ауту без списка тем. Если имя занято другим устройством, сначала разреши конфликт. При обновлении уже работающей интеграции её собственные темы ожидаемы.

Установи пакет, проверь конфигурацию и привяжи аккаунт:

```sh
apt install /root/wb-mqtt-dreame_0.1.0_all.deb
wb-dreame check
wb-dreame setup
systemctl status wb-mqtt-dreame --no-pager
journalctl -u wb-mqtt-dreame -n 30 --no-pager
```

В `setup` укажи облачный регион из приложения, электронную почту аккаунта Dreamehome и его пароль. Пароль вводится без эха. Выбери своего робота из списка. В интерфейсе WB открой раздел «Устройства». MQTT-устройство имеет путь `/devices/dreame_l40_1`. Драйвер подключается к локальному Mosquitto по `127.0.0.1:1883` через MQTT 5. Драйверу нужны чтение всех сохранённых тем и публикация в ветке этого устройства. При конфликте идентификатора смотри сообщение в панели и журнал службы. При штатной остановке карточка отмечается как отключённая. Если процесс завершился аварийно, последнее MQTT-показание может оставаться видимым до переподключения.

По умолчанию `allow_commands=false`. Кнопка «Проверить задание» запрашивает актуальное состояние и проверяет цель без движения. Для управления открой в настройках WB конфигуратор «Пылесос Dreame», включи «Разрешить запуск и команды движения с панели» и сохрани. Для просмотра карты и истории достаточно режима чтения. После включения разрешения отправка требует отдельного подтверждения в интерфейсе. Идентификатор и попытка фиксируются до обращения к роботу, тайм-аут оставляет результат неопределённым. Историю фактических уборок панель читает из Dreamehome. Перед отправкой задания проверь выбранную цель и убедись, что робот может безопасно начать движение.

## Панель «Пылесос»

На вкладке **Карта** выбери комнаты или зоны для разовой уборки. Кнопка **Слои** открывает настройки подложки и покрытия. **Сценарии** хранят повторяемые задания. **Расписание** показывает время уборок и зарядки. В **Истории** можно открыть карту конкретной уборки. В **Ресурсах** видны состояния и расходники робота и станции, а **Настройки** позволяют менять параметры самого робота.

Открой **Интеграции → Пылесос** (в английском интерфейсе **Integrations → Vacuum**). Страница открывается внутри HomeUI. Штатный веб-сервер WB передаёт запросы панели по локальному Unix-сокету. Для доступа по пути `/dreame/` нужны права администратора WB. Перезагрузи открытую ранее вкладку один раз после установки.

- **Комнаты.** Коснись комнаты на карте или её карточки в задании уборки. Номера показывают порядок уборки. До запуска можно убрать комнату из середины — остальные сдвинутся. Повторный выбор добавляет её в конец. При новой разбивке план перечитывается, и комнаты нужно выбрать заново.
- **CleanGenius.** Открой «Настройки» или нажми на строку CleanGenius в задании, затем выбери режим. Для умной уборки доступны вся квартира или комнаты. Режим выбирает мощность и подачу воды. На базе с промывкой можно начать новую уборку во время сушки, когда робот подтвердил зарядку, завершение прежнего задания и отсутствие неисправностей. Прямоугольные зоны доступны в ручном режиме.
- **Текущие настройки.** Нажми на нужный вариант и затем «Сохранить». Пометка «Сейчас» показывает значение робота. Мощность, воду и маршрут можно настроить в ручном режиме. Рядом с заблокированным параметром указана причина. Переключатель автодолива предназначен для базы с подключённым комплектом воды. Режим CleanGenius выбирается рядом с заданием уборки.
- **Зона.** Растяни прямоугольник мышью или пальцем. Перетащи его за середину, а размер измени за один из четырёх углов. Точные координаты можно задать числами. Рядом с выделением появятся размеры в метрах, площадь прямоугольника и площадь пола внутри него. Стены, неизвестные клетки и постоянные запретные области исключаются из расчёта пола. Фактически убранная площадь появится в истории.
- **План квартиры.** После установки видна собственная карта Dreame. Дополнительно поддерживается заранее откалиброванная подложка в файлах контроллера; загрузки произвольного рисунка через панель пока нет. Прозрачность регулируется на месте. «Подогнать план» меняет только рисунок. Координаты задания всегда принадлежат карте Dreame. Драйвер запоминает исходный контур калибровки на WB. Когда робот уточняет до 1 % клеток контура на той же карте и сетке, фон сохраняется. При большем расхождении или смене границ сетки фон скрывается до проверки выравнивания.
- **Где пылесос.** Во время уборки открой «Карта помещений». Значок показывает последнее положение робота, линия — записанный им путь. Рядом указаны комната и время кадра. Если Dreame ещё не прислал координаты, появится сообщение об ожидании.
- **Убранный пол.** Под текущей картой и в окне истории есть переключатель «Убранный пол». Голубая заливка на текущей карте показывает покрытие. Подпись «По данным Dreame» означает, что робот передал отмеченные клетки. «По влажным проходам» означает оценку по участкам пути, на которых робот пылесосил и мыл либо только мыл пол. Условная ширина полосы на плане — 25 см. Сухие проходы остаются линиями. В архиве с клетками Dreame зелёный показывает обработанные места, оранжевый — отмеченные роботом загрязнения. Выбор видимости запоминается в этом браузере и применяется к обеим картам.
- **История.** Нажми на запись, чтобы открыть карту именно той уборки. В окне видны результат, время, площадь, записанные проходы и препятствия. Доступны увеличение и переход к соседней уборке. Если запись содержит отдельный слой обработанного пола, он отображается поверх комнат. Фильтр по результату пересчитывает общее время и площадь видимых записей. Драйвер показывает до 30 последних уборок.
- **Воспроизведение.** Нажми «Воспроизвести» или передвигай ползунок, чтобы просмотреть движение в записанном порядке. Между отдельными проходами на карте остаётся разрыв. Скорость показа условная, поскольку в архивном пути нет времени каждой точки.
- **Препятствия и камера.** Нажми на значок карты или выбери препятствие в списке, чтобы посмотреть сохранённое фото при наличии разрешения Dreamehome. Выключи «Метки», чтобы рассмотреть линии проходов. Список препятствий останется доступен под картой. В разделе камеры видны возможности модели и состояние видеосеанса. Живое видео для L40s Pro Ultra открывается в приложении с кодом доступа. [Как устроены фото и камера](docs/CAMERA.md)
- **Состояние базы и расходники.** Открой «Ресурсы», чтобы увидеть, что обслужить у робота и станции. Где Dreame передаёт время, рядом с процентом видны дни или оставшиеся часы работы. Для двух щёток и фильтра оценка в календарных днях основана на средней длительности уборок за последние полные дни (от 7 до 28 дней истории). Она появляется, если есть уборки с известной длительностью хотя бы в три разных дня и робот убирал на последней неделе. У L40s Pro Ultra доступны [фотографии оборудования и совместимых деталей от Dreame](docs/PRODUCT_PHOTOS.md).

При установке пакет создаёт панель `dreame-control` через API HomeUI. Если интерфейс в момент установки был выключен, после его запуска выполни `wb-dreame install-panel`. Повторный вызов сохраняет пользовательскую панель. После успешной регистрации пакет снимает прежнюю обзорную панель `dreame-vacuum`, если она в точности совпадает со штатным шаблоном. Отредактированную владельцем панель он сохраняет. Для другого контроллера `wb-dreame panel` печатает её шаблон без личных данных.

**Комнаты и доуборка.** Во время работы робот может отмечать убранные и пропущенные комнаты. В архиве фиолетовым отмечены комнаты, где записан уборочный проход или покрытие. Под картой видно, откуда взялась отметка. Если Dreame сохранил слой убранного пола, рядом указана площадь этого слоя в комнате. Уборочный проход сам по себе не подтверждает завершение комнаты. Кнопка «Карта последней уборки» открывает датированный архив, когда робот простаивает. Чтобы вернуться к пропущенным комнатам или загрязнённым участкам, открой вкладку «История» или карту последней уборки и нажми «Доубрать». Панель проверит именно последний отчёт Dreamehome, покажет подтверждённые цели и попросит подтвердить запуск. Если робот не прислал цели, на экране появится причина. По одному отчёту разрешена одна отправка, в том числе если ответ на команду потерялся.

**Несколько зон.** Выбери «Зоны» и нарисуй до десяти прямоугольников, перетаскивая указатель от угла до угла на свободном месте. Касание выбирает зону, за центр её можно переместить, за край или угол — изменить размеры. Кнопка × на выбранной зоне удаляет её, а «Вернуть зону» отменяет последнее удаление. Для точного ввода раскрой координаты в задании. В подтверждении перечислены все зоны, на робот отправляется одно задание. Рисовать и сохранять можно при включённом CleanGenius, для запуска зон нужен ручной режим.

**Песок у входа.** На вкладке «Сценарии» у карточки «Песок у входа» нажми «Настроить» или «Изменить». Нарисуй зоны и выбери всасывание, подачу воды и число проходов. «Сохранить сценарий» записывает их на WB для всех устройств. «Как у робота» берёт соответствующее значение при запуске. Сценарии, созданные в preview22, сохраняют все прежние зоны и по умолчанию используют один проход и настройки робота. «Отмена» возвращает прежнее задание. Чтобы запустить сохранённый сценарий, нажми «Подготовить уборку», проверь параметры и подтверди запуск. После переименования или разделения комнат участок сохраняется, если пол у входа и привязка карты совместимы.

**Сценарии Dreamehome.** В том же разделе нажми название уже созданного в приложении сценария. Панель проверяет текущую карту и состав задания. При включённом управлении открывается подтверждение с целями и числом этапов; в режиме просмотра выполняется только проверка. Параметры хранятся в Dreamehome. После изменения списка нажми «Обновить».

Для сценария у входной двери в репозитории есть [пример wb-rules](examples/README.md). Он вызывает только предпросмотр и требует подтверждённых канала двери, полярности контакта и цели на карте. Правило не устанавливается автоматически.

## Расписания и история

Во вкладке **Расписание** панель показывает задания из Dreamehome, время и дни недели. На L40s Pro Ultra у обычного задания можно изменить время и включение, у повторяющегося — также дни. Кнопка «Создать копию» переносит комнаты и режим выбранного задания. Укажи дни и время, затем при необходимости включи сохранённую копию. Отменить задание можно переключателем, удалить — с подтверждением. Первое задание для пустого списка и смена комнат или режима расписания пока доступны в Dreamehome. На других моделях предусмотрен просмотр.

Изменения разрешены при включённом управлении. Перед записью драйвер заново сверяет список с роботом, сохраняет параметры соседних заданий и проверяет результат чтением. Если расписание изменилось, открой свежий список. На поддерживаемых устройствах здесь же можно включить, выключить и настроить интервал непиковой зарядки.

История поступает из Dreamehome. Драйвер дополнительно сверяет последние 30 записей примерно раз в пять минут. Это подхватывает уборки, если облако задержало отчёт или пропущено событие завершения. При ошибке чтения последняя полученная история остаётся доступной в работающей службе.

## Что хранится в MQTT

Драйвер публикует сообщения под `/devices/dreame_l40_1/controls/`. У каждого сообщения выставлен флаг `retain` — брокер отдаёт последнее значение при новой подписке. Длительную историю измерений может отдельно записывать настроенный на WB регистратор.

| Канал | Последнее значение |
|---|---|
| `state_connection` | Состояние связи драйвера с Dreamehome или сообщение о необходимости привязки |
| `state_robot` | Исходный код состояния, например `DRYING`. Карточка использует подписи состояний WB |
| `level_battery` | Заряд в процентах |
| `fw` | Версия прошивки робота |
| `map_id` | ID выбранной карты Dreame |
| `rooms` | Исходный JSON для правил. Скрыт в карточке устройств |
| `room_<номер>` | Имя отдельной комнаты выбранной карты. Если для комнаты задано имя в конфигураторе WB, отображается оно. Номера совпадают с номерами Dreame |
| `map_frame` | Статический снимок плана в формате SVG, закодированный в Base64, для обзорной панели и сценариев |

В `meta` публикуются описание устройства и подписи каналов; `meta/error` сообщает об ошибке чтения. При пропаже связи последнее число на канале может остаться прежним. Учитывай признак ошибки в автоматизации.

Интерактивная панель запрашивает службу WB по `/dreame/api/`. Положение и маршрут поступают из карты Dreame, состояние базы и настройки — из показаний робота. Архивные карты и разрешённые снимки загружаются из облака при открытии. Свои имена комнат, подложка, привязка аккаунта и журнал отправленных команд хранятся в файлах на WB. Кнопки панели обращаются к веб-службе. Управления движением через входящие MQTT-топики в этой версии нет.

## Обновление и возврат

Перед обновлением [сохрани личную копию](#сохранить-копию-на-пк) и оставь у себя `.deb` текущей версии. Скопируй новый пакет на WB, как при первой установке, затем проверь `apt-get -s install /root/ИМЯ-НОВОГО-ПАКЕТА.deb`. Если предлагаемые изменения подходят, выполни на WB:

```sh
apt install /root/ИМЯ-НОВОГО-ПАКЕТА.deb
wb-dreame check
systemctl is-active wb-mqtt-dreame
```

Для возврата с версии 0.1.0 на предварительный выпуск скопируй сохранённый прежний пакет на WB. Останови драйвер и сними его сохранённые сообщения MQTT, пока установлена новая версия. После аварийной остановки в брокере могут оставаться отдельные каналы комнат, которые прежний пакет ещё не распознаёт. Утилита очищает только сообщения с меткой этой установки.

```sh
systemctl stop wb-mqtt-dreame && wb-dreame clear-retained &&
  apt install --allow-downgrades /root/ИМЯ-ПРЕЖНЕГО-ПАКЕТА.deb &&
  systemctl start wb-mqtt-dreame && wb-dreame check
systemctl is-active wb-mqtt-dreame
```

Если очистка сообщает, что MQTT недоступен, восстанови связь с локальным брокером и повтори команды. Чтобы продолжить работу на текущей версии, выполни `systemctl start wb-mqtt-dreame`.

Настройки при обычном обновлении и возврате сохраняются. Если потребуется восстановить именно старые настройки, используй личную копию по инструкции ниже; не распаковывай её поверх действующего каталога.

## Настройки и операции с пакетом

| Операция | Что происходит |
|---|---|
| Первичная установка | Пакет создает настройки по умолчанию, если их еще нет. После запуска в разделе «Устройства» появляется статус привязки |
| Установка новой версии .deb | Системные файлы обновляются, конфиг и привязка сохраняются. Новую версию устанавливают через `apt install /путь/к/новому.deb` |
| Установка той же версии | `apt install --reinstall /root/wb-mqtt-dreame_0.1.0_all.deb` |
| Снятие расширения | `apt remove wb-mqtt-dreame` сохраняет настройки и привязку для повторной установки |
| Полное удаление собственных настроек | `apt purge wb-mqtt-dreame` стирает конфиг, пароль, сохранённую сессию и идентификатор установки MQTT. Внешние резервные копии сохраняются |
| Обычное совместимое обновление WB через APT | Пакет остается установленным. При смене Debian снова проверь совместимость зависимостей |
| Чистая замена rootfs через FIT при сохраненном отдельном /mnt/data | Верни .deb с ПК и установи его еще раз. Он подхватит настройки. При сбросе данных нужна внешняя копия |

При удалении брокер MQTT должен быть доступен, чтобы драйвер успел снять свои сохранённые показания. После обычного `remove` идентификатор установки остаётся для повторной установки.

Изменяемые файлы лежат в `/mnt/data/etc/wb-mqtt-dreame/`. `config.json` хранит интервал опроса, `account.json` — привязку и пароль с правами 0600, `state/session.json` — токен для продолжения сеанса, `state/entrance.json` — зоны и параметры сценария «Песок у входа». При сохранении через редактор оставляй основной конфиг доступным службе для чтения. После правки выполни `wb-dreame check && systemctl restart wb-mqtt-dreame`.

## Сохранить копию на ПК

Свои названия комнат задавай в **Настройки → Конфигурационные файлы → Пылесос Dreame**, рядом с интервалом опроса. Драйвер формирует список по сохранённой карте робота. Впиши имя в строку комнаты и сохрани форму. Пустое имя возвращает название из Dreamehome. Чтобы увидеть изменения после разделения или объединения комнат, открой форму заново. При изменившейся карте редактор попросит перечитать список.

При первом изменении имён конфигуратор записывает их в `config.json`. До тех пор драйвер читает прежний `state/room-names.json`. Перед возвратом к preview20 сохрани последующие изменения отдельно и восстанови из копии прежний `config.json`.

Ниже команды PowerShell для контроллера с работающей службой. Делай копию, когда робот на базе. На время архивации останавливается только драйвер Dreame, чтобы журнал заданий, сессия и подложка попали в архив согласованно. Копию с паролем, токеном и планом квартиры храни в личной папке вне Git.

```powershell
$stamp = Get-Date -Format yyyyMMdd-HHmmss
$remote = "/root/dreame-backup-$stamp.tar.gz"
ssh root@WB_ADDRESS "set -eu; umask 077; systemctl is-active --quiet wb-mqtt-dreame; trap 'systemctl start wb-mqtt-dreame' EXIT; systemctl stop wb-mqtt-dreame; tar -C /mnt/data/etc -czf '$remote' wb-mqtt-dreame"
if ($LASTEXITCODE -eq 0) {
    scp "root@WB_ADDRESS:$remote" "$env:USERPROFILE\dreame-backup-$stamp.tar.gz"
}
```

Для восстановления на чистой системе скопируй свой архив на WB, просмотри `tar -tzf /root/ИМЯ-КОПИИ.tar.gz`. В нем должны находиться только файлы каталога расширения. До установки .deb распакуй копию в `/mnt/data/etc`. Команда ниже откажется восстанавливать поверх существующих настроек. При первом старте служба назначит файлу сессии актуального служебного пользователя.

```sh
test ! -e /mnt/data/etc/wb-mqtt-dreame && tar --no-same-owner -C /mnt/data/etc -xzf /root/ИМЯ-КОПИИ.tar.gz
```

## Сборка и проверка

В Linux или WSL из папки проекта выполни `sh build.sh`. Нужен `dpkg-deb`. Зависимости Python нужны для запуска службы и unit-тестов. В этой версии они ставятся как пакеты Debian, без установки библиотек через pip в системный Python. Запуск тестов на Debian 13 с зависимостями из `packaging/control`:

```sh
PYTHONPATH=src /usr/bin/python3 -m unittest discover -s tests -v
unshare -Ur sh tests/package-cycle.sh
```

Проверка геометрии, выбора комнат и зон, восстановления запроса, архивных карт и воспроизведения маршрутов на ПК — `node --test tests/test_dreame_web.mjs tests/test_dreame_history.mjs`.

Сценарий `tests/package-cycle.sh` проверяет установку, переустановку, обновление, удаление и возврат пакета, а также замену корневого раздела при сохранении данных. После каждого этапа он сравнивает контрольные суммы настроек.
